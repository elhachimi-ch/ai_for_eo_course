What is a foundation model?

Definition

A model pre-trained on massive datasets with self-supervised objectives and adaptable to many downstream tasks.

  1. Massive EO archive — petabytes of unlabelled imagery
  2. Self-supervised pre-training — masking, contrast, distillation
  3. General geospatial representation — one encoder
  4. Fine-tuning → many downstream tasks
NLP · GPT, LlamaVision · DINOv2, SAMGeo · Prithvi, TerraMind, Galileo, AnySat
Definition and figure taken from the GeoFM seminar deck. DOFA's idea: a wavelength-conditioned patch embedding lets one encoder accept optical, multispectral, hyperspectral and SAR inputs.

Four ways to learn without labels

Reconstruction · MAE, SatMAE

Mask ~75% of patches, reconstruct pixels → fine spatial detail.
\(\mathcal{L}=\tfrac{1}{|M|}\sum_{p\in M}\lVert \hat{\mathbf{x}}_p-\mathbf{x}_p\rVert^2\)

Contrastive · CLIP, RemoteCLIP

Pull matching pairs together, push others apart → semantics.
\(\mathcal{L}=-\log\frac{e^{\mathrm{sim}(z_i,z_i^+)/\tau}}{\sum_j e^{\mathrm{sim}(z_i,z_j)/\tau}}\)

Distillation · DINO, DINOv2

Student matches a momentum teacher on different crops/views → strong semantic features, no negatives.

Predictive · JEPA

Predict the latent representation of masked regions, not pixels → abstract “world-model” features.

In EO a natural “positive pair” is the same place seen by two sensors or on two dates — free supervision from geography.
Four families from the seminar deck, with the defining loss for the two simplest. The EO-specific twist on contrastive learning (SeCo, CROMA, DeCUR) is to use co-located multi-sensor or multi-temporal views as positives.

How an LLM is made — three stages

①

Pre-training

Decoder-only Transformer predicts the next token on trillions of tokens:

$$\mathcal{L}=-\sum_t \log p_\theta(x_t\mid x_{<t})$$

Scaling laws: loss falls predictably with parameters, data, compute (Chinchilla: ≈ 20 tokens per parameter).

②

Instruction tuning

Supervised fine-tuning on (instruction, answer) pairs turns a text-completer into an assistant. PEFT/LoRA makes this affordable for domain models (e.g. climate, EO).

③

Alignment & reasoning

RLHF / DPO learn from human preferences — Turing's rewards and punishments, 75 years later. RL on verifiable tasks yields “reasoning” models (o1, DeepSeek-R1).

Timeline

GPT-1 (2018) → GPT-3 (2020, 175 B) → ChatGPT (2022) → open-weight families (Llama, Mistral, Qwen, DeepSeek) and multimodal models that read images and maps.

Limits that matter for science

Hallucination, stale knowledge, no access to your data, weak arithmetic on rasters — which is why we add retrieval and tools.

Close the historical loop: the RLHF stage is literally the reward/punishment education Turing proposed in 1950. Stress that an LLM alone cannot compute an NDVI over a city — it needs tools.

Talking to an LLM: tokens, prompts, embeddings

Tokens

Text is split into sub-word tokens (“evapo|transp|iration”). Context windows, cost and speed are counted in tokens. Arabic and French often need more tokens than English.

Prompt patterns

  • Role + task + constraints + format
  • Few-shot examples
  • Step-by-step reasoning
  • Ask for citations / “say if unknown”

Embeddings

A text (or image, or pixel!) becomes a vector; similar meaning ⇒ nearby vectors. Search = nearest neighbours by cosine similarity — the engine of RAG, and the same idea as AlphaEarth.

SYSTEM = """You are an Earth-observation analyst.
Use ONLY the provided context and tool outputs. If the answer is not there, say so.
Return: (1) a short answer, (2) the evidence with [source, page], (3) caveats
(sensor, resolution, date, cloud cover)."""
USER = "Which Sentinel-2 bands are at 10 m and which index detects built-up areas?"

Knowledge lives in the index, not the weights: update documents, no retraining.

EO use cases

  • Q&A over mission handbooks, ATBDs, product specs
  • Search a lab's past reports and theses
  • Policy docs + maps: “what does the regional plan say about this zone?”
  • Retrieve similar image chips via EO embeddings (multimodal RAG)
Common failure modes: bad chunking (tables split), retrieving the wrong section, and the model ignoring context. Evaluate retrieval (did the right chunk come back?) separately from generation.

Lab 10 · A cited RAG assistant for EO documents

from langchain_community.document_loaders import PyPDFLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_huggingface import HuggingFaceEmbeddings
from langchain_community.vectorstores import FAISS
from langchain.chat_models import init_chat_model

docs = []
for f in ["S2_user_handbook.pdf", "zhu2026_earth_fm.pdf"]:
    docs += PyPDFLoader(f).load()                  # one doc per page
chunks = RecursiveCharacterTextSplitter(
    chunk_size=1000, chunk_overlap=150).split_documents(docs)

emb = HuggingFaceEmbeddings(model_name="BAAI/bge-small-en-v1.5")
db = FAISS.from_documents(chunks, emb)
retriever = db.as_retriever(search_kwargs={"k": 4})
llm = init_chat_model("ollama:qwen2.5:7b")         # or "openai:..." etc.

def ask(q):
    ctx = retriever.invoke(q)
    context = "\n\n".join(
        f"[{d.metadata['source']} p.{d.metadata.get('page', 0) + 1}] "
        f"{d.page_content}" for d in ctx)
    msg = [("system", SYSTEM), ("user", f"Context:\n{context}\n\nQ: {q}")]
    return llm.invoke(msg).content

print(ask("What are the 11 features of an ideal Earth foundation model?"))
