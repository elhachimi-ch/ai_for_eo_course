Why now? Data × algorithms × compute

◈

Data

  • ImageNet (2009): 14 M labelled images
  • Landsat archive opened free in 2008
  • Copernicus Sentinels: free & open, petabytes per year
  • Labels from crowdsourcing & OpenStreetMap
∂

Algorithms

  • ReLU: gradients that do not vanish
  • Dropout, batch-norm, Adam
  • Residual connections (ResNet): 100+ layers
  • Self-supervised pre-training
▦

Compute

  • GPUs: thousands of cores for matrix maths
  • CUDA (2007) made them programmable
  • TPUs & tensor cores (2016–17)
  • Cloud platforms: Earth Engine, Planetary Computer
All three were necessary. The 1986 back-prop algorithm already existed; what was missing was data at scale and hardware to multiply matrices quickly. Earth observation followed the same path a few years later once open archives and cloud computing met.

One dense layer = one matmul: \(\mathbf{Y}=\mathbf{X}\mathbf{W}\). For a batch of 256 Sentinel-2 patches through ResNet-50 that is ≈ 1–2 TFLOP per forward pass — seconds on a CPU, milliseconds on a GPU.
2012: AlexNet trained on two consumer GTX 580 GPUs and won ImageNet by a wide margin — the moment the field switched.
The ResNet-50 number: about 4 G multiply–adds (≈ 8 GFLOP) per 224×224 image, so a batch of 256 is on the order of 1–2 TFLOP. Emphasise orders of magnitude, not exact marketing numbers.

Training compute grew ~10 orders of magnitude

  • Before 2010 compute followed Moore's law (doubling ≈ every 2 years).
  • In the deep-learning era it doubled roughly every ~6 months (Sevilla et al., 2022).
  • Scaling laws: loss falls as a power law of parameters, data and compute — the bet behind LLMs and Earth foundation models.
  • Cost now matters: carbon-aware training is one of the “ideal Earth FM” features (Chapter V.7).

From the logical neuron to the perceptron

McCulloch–Pitts (1943) — binary inputs, fixed weights, threshold θ; can implement AND, OR, NOT: \(\;y=\mathbb{1}\big[\textstyle\sum_i w_i x_i \ge \theta\big]\)
Rosenblatt (1958) — real inputs, weights learned from errors:
$$\hat y = \operatorname{sign}(\mathbf{w}^\top\mathbf{x} + b),\qquad \mathbf{w}\leftarrow \mathbf{w} + \eta\,(y-\hat y)\,\mathbf{x}$$

Convergence theorem (Novikoff, 1962)

If the classes are linearly separable with margin γ and \(\lVert\mathbf{x}\rVert\le R\), the perceptron makes at most \((R/\gamma)^2\) mistakes — then stops. If they are not separable, it never settles.

Rosenblatt's Mark I Perceptron was hardware: a 20×20 photocell “retina”, potentiometer weights driven by motors.

Stress the two innovations: real-valued inputs and a learning rule — the Turing loop from Part I made concrete. The convergence theorem is both the promise (guaranteed learning) and the catch (only if linearly separable).

XOR: the 1969 critique

Load XOR: no straight line works, the error never reaches 0. Minsky & Papert proved single-layer limits; funding dried up for a decade.

The fix — hidden layers + a differentiable activation + back-prop — took until 1986 to catch on.

Gradient descent — walk downhill

$$\theta_{t+1} = \theta_t - \eta\,\nabla_\theta \mathcal{L}(\theta_t)$$
  • Learning rate η: too small = slow, too big = divergence or oscillation. Try it →
  • Stochastic GD: estimate \(\nabla\mathcal{L}\) on a mini-batch of 32–512 patches; noise helps escape poor minima.
  • Momentum / Adam: average past gradients and rescale per parameter — the default optimisers today (AdamW for Transformers).
  • Non-convex loss: start point and η decide which valley you land in.
Live demo: with η = 0.3 from θ₀ = 2.6 the ball reaches the right-hand minimum. Push η to about 1.2+ and it oscillates or jumps valleys. Start at −2.8 to land in the deeper left minimum. This is the whole of training, in one dimension.

Multi-layer perceptron: stack, bend, repeat

$$\mathbf{h}^{(\ell)} = \phi\!\left(\mathbf{W}^{(\ell)}\mathbf{h}^{(\ell-1)} + \mathbf{b}^{(\ell)}\right),\quad \mathbf{h}^{(0)}=\mathbf{x}$$
  • Each layer = linear map (rotate/stretch) + non-linear bend φ. Without φ the whole net collapses to one linear map.
  • Hidden layers solve XOR: they re-represent the input so classes become linearly separable at the last layer.
  • Universal approximation (Cybenko 1989; Hornik 1991): one wide hidden layer can approximate any continuous function on a compact set — but depth makes it far more efficient.
  • Parameters: 13→128→64→10 has 13·128+128 + 128·64+64 + 64·10+10 = 10 698 weights.
Parameter count check: 1792 + 8256 + 650 = 10 698. MLPs are the right tool when your input is a vector without spatial structure: a pixel spectrum, a set of tabular features, or an embedding vector (we will use MLP heads on top of foundation-model embeddings later).

Back-propagation = the chain rule, applied backwards

$$\frac{\partial L}{\partial w} = \frac{\partial L}{\partial \hat y}\cdot\frac{\partial \hat y}{\partial z}\cdot\frac{\partial z}{\partial w} = 2(\hat y - y)\,\sigma(z)\big(1-\sigma(z)\big)\,x$$
  • Forward pass computes and caches every intermediate value.
  • Backward pass multiplies local derivatives from the loss back to each weight — one sweep gives all gradients at ≈ the cost of one forward pass.
  • PyTorch/JAX do this automatically (autograd): you write the forward pass, loss.backward() does the rest.
  • Products of many small factors (σ′ ≤ 0.25) ⇒ vanishing gradients in deep or recurrent nets — the motivation for ReLU, ResNets and LSTMs.
Walk the dashed red arrows right to left. The final bullet sets up three later stories: ReLU (two slides on), residual connections (Chapter V.2) and LSTM gates (Chapter V.3) are all fixes for the vanishing-gradient problem.

Activation functions: where the non-linearity lives

\(\sigma(z)=\frac{1}{1+e^{-z}}\) — probabilities, gates in LSTMs. Saturates ⇒ vanishing gradients.

\(\tanh z\) — zero-centred, used in RNN/LSTM states. Also saturates.

\(\max(0,z)\) — cheap, gradient 1 when active. Default for CNNs since AlexNet.

\(z\,\Phi(z)\) — smooth ReLU used in Transformers (BERT, ViT, Prithvi).

Output layer follows the task, not fashion: linear for regression (ETo in mm/day), sigmoid for binary masks (slum / non-slum), softmax for K classes (land cover).
Quick slide. The only thing to remember: hidden layers use ReLU/GELU; outputs match the loss (sigmoid + BCE, softmax + CE, linear + MSE).

A training recipe that works in EO

1 · Data

  • Normalise per band (mean/std of the training set)
  • Spatially blocked train / val / test
  • Augment: flips, 90° rotations, (careful) brightness
  • Handle imbalance: class weights, focal loss

2 · Optimisation

  • AdamW, lr 1e-3 (scratch) or 1e-4 (fine-tune)
  • Mini-batches 32–256; cosine or one-cycle schedule
  • Mixed precision on GPU
  • Early stopping on validation loss

3 · Regularisation

  • Weight decay \(\lambda\lVert\theta\rVert^2\)
  • Dropout (p = 0.1–0.5)
  • Batch / layer normalisation
  • Pre-trained weights (transfer)

Diagnose

Train ↓ val ↑ ⇒ over-fitting · both high ⇒ under-fitting / bad lr · val ≫ test on a new region ⇒ domain shift.

Report

Per-class F1, IoU, confusion matrix, and the map — numbers alone hide spatial errors.

This recipe is reused in every lab. The band normalisation statistics must come from the training split only. In EO, “test on a new region” is the honest test.

Lab 4a · A perceptron in 20 lines of NumPy

import numpy as np

class Perceptron:
    """Rosenblatt (1958) with labels in {-1, +1}."""
    def __init__(self, n_features, lr=0.01):
        self.w = np.zeros(n_features); self.b = 0.0; self.lr = lr

    def predict(self, X):
        return np.where(X @ self.w + self.b >= 0, 1, -1)

    def fit(self, X, y, epochs=100):
        self.errors_ = []
        for _ in range(epochs):
            errors = 0
            for xi, yi in zip(X, y):
                if yi * (xi @ self.w + self.b) <= 0:   # mistake
                    self.w += self.lr * yi * xi         # update rule
                    self.b += self.lr * yi
                    errors += 1
            self.errors_.append(errors)
            if errors == 0:                             # converged
                break
        return self

from torchgeo.datasets import EuroSAT
ds = EuroSAT("data", split="train", bands=("B04", "B08"),
             download=True)
veg, water = {"Forest", "Pasture"}, {"River", "SeaLake"}
X, y = [], []
for s in ds:
    name = ds.classes[int(s["label"])]
    if name in veg | water:
        X.append(s["image"].mean(dim=(1, 2)).numpy() / 1e4)
        y.append(1 if name in veg else -1)
X, y = np.array(X), np.array(y)
p = Perceptron(2, lr=0.05).fit(X, y)
print("train acc:", (p.predict(X) == y).mean())
Expected: near-perfect accuracy within a few epochs. Then try Highway vs Industrial — the error count no longer reaches 0 (not separable).
EuroSAT-MS stores digital numbers scaled by 10 000; dividing by 1e4 gives approximate reflectance. Band selection with the bands= argument is supported by TorchGeo's EuroSAT. The notebook adds plots of the decision line and the error curve.
